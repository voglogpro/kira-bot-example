# Учебный бот KIRA: вопросы → заявка → CRM

Официальный технический пример для Кира Конструктора: бот спрашивает имя и email, затем собирает ответы в заявку. В репозитории находится экспорт сценария из шести шагов и пяти связей. Его можно импортировать в новый проект и проверить путь от вопроса до CRM. Это учебная заготовка для разбора механики, без подключений к настоящему боту и заранее заполненных контактов.

Сценарий хранится в [bot-lead-example.json](bot-lead-example.json). [Официальный источник JSON](https://kirakonstruktor.ru/examples/bot-lead-example.json) и [инструкция с изображением учебной CRM](https://kirakonstruktor.ru/konstruktor-botov#bot-lead-example) позволяют сверить файл и ожидаемый результат.

## Импорт

1. Скачайте JSON из репозитория или официального источника.
2. Создайте новый пустой проект в Кира Конструкторе. Используйте отдельный проект, чтобы учебный импорт не заменил ваш рабочий сценарий.
3. В редакторе на компьютере нажмите **«Найти» → «Загрузить JSON»**, выберите скачанный файл и подтвердите замену черновика.
4. Проверьте, что появились шесть шагов, соединённых в один маршрут. Сохраните черновик. Импорт и сохранение сами по себе не публикуют бота.

## Что находится внутри

Маршрут начинается со старта. Сообщение предлагает оставить заявку; кнопка **«Оставить заявку»** ведёт к вопросам. Первый вопрос сохраняет имя в переменную `name`, второй — email в `contact`. У email задана проверка формата. Затем шаг **«Заявка»** собирает поля «Имя» и «Email». Последнее сообщение завершает учебный диалог.

Заготовка не проверяет свободные места в календаре и не подтверждает время консультации автоматически. Учебные тексты нужно заменить перед работой с клиентами.

## Проверка результата

Сначала пройдите личный тест в конструкторе: нажмите кнопку заявки, введите «Учебный клиент» и `demo@example.test`. Убедитесь, что вопросы идут по порядку, а собранные значения видны в результате проверки. Можно отдельно проверить неверный email и повторный запрос ответа.

**Личный тест не отправляет рабочую заявку в CRM.** Чтобы проверить рабочую доставку:

1. Если проверяли черновик в своём Telegram-боте, завершите личный тест командой `/stop`.
2. Подключите своего бота в проекте и отдельно опубликуйте проверенный сценарий.
3. Отправьте боту `/start` без тестовой ссылки и оставьте контрольную заявку. Используйте учебные данные, чтобы отличать проверку от настоящих обращений.

Затем откройте CRM проекта и нажмите **«Импортировать заявки»**. Если в контрольной заявке использованы то же имя и email, в списке «Клиенты» появится запись «Учебный клиент» с адресом `demo@example.test`. После изменений черновика рабочую версию обновляют отдельной публикацией.

## Проверка файла локально

При установленном Node.js выполните:

```sh
node check-json.mjs
```

Скрипт сверяет SHA256 исходного файла, связи и достижимость шести шагов. Это структурная проверка, **не запуск KIRA runtime**: она не проверяет интерфейс, подключение мессенджера, публикацию или доставку заявки в CRM. Эти действия проверяются отдельно по инструкции выше. Изменённый JSON не пройдёт проверку исходного SHA256.
